Build a polished, production-minded mobile MVP using Expo, React Native, and TypeScript.

The working product name is:

BAD LUCK OR SKILL ISSUE?

Tagline:

Track every roll. Settle every excuse.

PRODUCT VISION

This app helps people playing physical tabletop games record dice rolls, track players, understand whether outcomes were unusually lucky or unlucky, and generate humorous, shareable end-of-game results.

The app is also the software foundation for a future physical tabletop device with a large clickable rotary dial, screen, rechargeable battery, and supporting buttons.

The mobile app itself should not use a rotary-dial interface. It should use an extremely fast number-entry interface optimized for recording physical dice rolls with as few taps as possible.

The app must be fully usable without creating an account.

Do not put a login screen, account requirement, subscription prompt, or onboarding wall between the user and starting a game.

The initial product should feel complete as a local, offline-capable app while remaining architecturally ready for:

* Optional user accounts
* Cloud synchronization
* Friend groups
* Social sharing
* Bluetooth hardware input
* Additional game-specific modes
* Premium analytics packs
* Android and iOS store distribution

CORE PRODUCT PRINCIPLES

1. Starting a game should be fast.
2. Recording a roll should require one tap whenever possible.
3. The app should be usable without internet access.
4. No account should be required for core use.
5. Statistics must be accurate and responsibly described.
6. The app should be entertaining without pretending to measure strategy it cannot observe.
7. The architecture must remain portable outside Replit.
8. All roll inputs must use the same input-neutral event service.
9. The future physical device must be able to submit rolls without rewriting the statistics or session systems.
10. Avoid unnecessary complexity in the first version.

NUMBER ENTRY INTERFACE

Do not use a rotary dial in the mobile app.

Use a fast number-button interface.

For D4, D6, D8, D10, D12, and D20:

* Display every possible result as a large tappable button
* Use a responsive grid
* Keep all buttons visible without unnecessary scrolling when practical
* Make each button large enough for quick use around a table
* Record the value immediately when tapped
* Provide clear visual and haptic confirmation
* Advance the player automatically when enabled

For 2D6 Total:

* Display totals 2 through 12
* Arrange the values logically
* Make 6, 7, and 8 no harder to enter than other values
* Record the total with one tap
* Optionally allow long-pressing or opening a secondary control to record the two individual die values

For Custom Range:

* Use a responsive number grid for manageable ranges
* For very large ranges, use a numeric keypad and confirmation control
* Clearly show the selected value before confirmation when one-tap entry is not practical

Provide persistent controls for:

* Undo Last Roll
* Previous Player
* Next Player
* Statistics
* End Game

Undo must be immediately available and require only one tap.

ROBBER TRACKING

Robber tracking must be optional.

In Quick Mode:

* Allow the user to mark a player’s exposure to a selected number as blocked
* Allow the block to be removed later

In Detailed Mode:

* Allow blocking a specific entered location
* Apply the block only during the turns when it was active

Clearly explain that results are more accurate when robber effects are entered.
